# Make the template your application

The included ACSys query, CLI, and optional PyQt window are **examples to customize or replace**. ACSys is included as a normal dependency, separate from the sample code. You can make a command-line, headless, or desktop program; use the libraries your app needs. First [create and rename your repository](quickstart.md), then work in that new repository.

## How the example is connected

The package in [`src/ap_python_starter_kit/`](../src/ap_python_starter_kit/) is installed according to [`pyproject.toml`](../pyproject.toml). Its `[project.scripts]` entry maps the installed `ap-python-starter-kit` command to [`main()`](../src/ap_python_starter_kit/main.py). The example's [`main.py`](../src/ap_python_starter_kit/main.py) defines `--device` and `--gui`: without `--gui` it prints five readings, and with `--gui` it opens the sample [`gui.py`](../src/ap_python_starter_kit/gui.py) window. Both paths call helpers in [`acsys_client.py`](../src/ap_python_starter_kit/acsys_client.py), which use the ACSys library declared as a runtime dependency with a Git source in [`pyproject.toml`](../pyproject.toml). The default request is `G:SCTIME@P,15H`; actual data requires ACSys access and any applicable site authentication.

The rename script updates the example package paths, links, and installed command in this guide to match your new project. Review them if you later move the entry point or remove the sample modules.

## Replace the example, step by step

1. **Choose what your app does.** Decide what should happen when someone runs your installed command, what inputs it needs, and whether it needs a window. You can start with a simple command that prints a result and expand from there.
2. **Edit your package's entry point.** Open your package's [`main.py`](../src/ap_python_starter_kit/main.py). Change its argument parser and default behavior to run **your** application. Replace the example `--device` flag, ACSys request, five-reading loop, and `--gui` switch if they do not fit. Keep a callable entry point returning an exit status, or change the `[project.scripts]` mapping in [`pyproject.toml`](../pyproject.toml) to your new callable. Then `uv sync --dev` refreshes the installed command. Running your command with `--help` is a useful check if you retain an argument parser.
3. **Adapt the demo code and add what your app needs.** The example [`acsys_client.py`](../src/ap_python_starter_kit/acsys_client.py) wraps ACSys DPM calls for the sample request. You can adapt that wrapper or call ACSys from your own code. If you do not use the wrapper, update its imports and clean up unused demo code so the launcher starts your code. Add other libraries as needed, then run `uv sync` and review changes to [`uv.lock`](../uv.lock); see [Dependencies and environment](development.md#dependencies-and-environment).
4. **Decide whether you want a desktop window.** For a CLI or headless app, remove the unused GUI branch and module, and remove the `gui-pyqt` extra if you no longer need PyQt. For a desktop app, customize the example window and update thread in [`gui.py`](../src/ap_python_starter_kit/gui.py) for your own UI and data flow; you can still use ACSys. If you prefer another toolkit, declare its dependencies and arrange for its entry point to launch. To try the *unchanged* sample GUI, use `uv sync --extra gui-pyqt` and `uv run ap-python-starter-kit --gui`. The [DevPod desktop](devpod.md#desktop-access) lets you see a window during development.
5. **Choose how your app is delivered.** For a CLI/headless application, choose the `cli` image variant in the provided workflow; for a desktop app, `gui-xpra` provides browser access to its window. Most changes **inside the renamed entry point** need no image startup changes: the rename script updates the original module names in both startup scripts. Only if you move or replace that entry point must you update the fixed launch command in [`docker/start-cli.sh`](../docker/start-cli.sh) or [`docker/start-gui.sh`](../docker/start-gui.sh) to launch your code. Both entrypoints use [`docker/create-workspace.sh`](../docker/create-workspace.sh), which requires writable storage mounted at `/mnt/storage`; see [Workspace storage](container.md#workspace-storage). You do not need to build images locally to deliver your app. See [CI and deployment](deployment.md) for the normal release path and [Container usage](container.md) for optional local image tests and startup details.
6. **Make tests describe your app.** Replace the example behavior checks in [`tests/test_main.py`](../tests/test_main.py) with tests for your arguments, command behavior, and any window logic you retain. Existing tests mock the ACSys reader; they do not confirm real ACSys connectivity. Run `uv run pytest`, followed by the quality checks in [Everyday development](development.md#tests-and-code-quality), and keep the [uv project compatible with integration](development.md#stay-compatible-with-integration). Commit your changes on a branch and follow [CI and deployment](deployment.md) when ready to deliver.
